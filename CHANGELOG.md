# Changelog

All notable changes to the Signal & Noise theme are documented here.

This file holds two things only: **`## [Unreleased]`**, the working log that
accumulates across pull requests, and the **current release**. Everything older
lives in [docs/changelog/](docs/changelog/).

A pull request does not bump `Version` and does not tag — it closes an issue and
adds a bullet below. A release is a separate, deliberate act:
`tools/cut-release.sh`, which stamps `style.css` **and** `readme.txt` together.

## [Unreleased]

### Fixed
- **The theme's own Copilot tool-schema normalizer was a hand-rolled twin of OpenStation's `openstation_ai_normalize_tool_schema()`, registered on a hook name OpenStation dropped at v1.0.0.** `inc/desktop-mode-copilot-schema.php` hooked `desktop_mode_ai_tools` alone, so on every release the site has run since August it never fired, while its docblock and the `functions.php` require line promised a guard the theme did not provide. Read: OpenStation's `docs/hooks-reference.md` names `openstation_ai_tools` as the Stable tool-list filter, and `includes/ai-copilot/search.php` at v1.1.10 normalizes every tool schema itself after that filter (the union top-level `type`, top-level `anyOf`/`oneOf`/`allOf`, empty `properties`, idempotent), which is the converter the module's docblock said should own this. Upstream has done this since v0.9.6 (2026-07-23, upstream #366, the fix for #362; the `openstation_` name since v1.0.0), one week after the theme's module was born in 10.42.3 citing that same #362, so the module was redundant on every release but the first week and dead by name on every release since August. The module, its require line, its file-map row and `tests/desktop-mode-copilot-schema.php` are deleted; the three shapes the theme declares are untouched and now pinned in `tests/abilities-registration.php` (+3: the top-level `anyOf`, the `object|null` union type, the empty `properties`). Nothing on screen changes: the module filtered an admin request the Copilot builds, never public output, and on the live site (OpenStation 1.1.10, companion plugin active) it was not running at all. Pinned by derivation in `tests/openstation-hook-names.php` (7): every hook name the theme registers or fires is read off the source with `token_get_all()` (a regex stripper opened a comment on the `styles/*.json` inside a description string and swallowed 225 lines of `inc/abilities-diagnostics.php`; found in review), a constant first argument resolves through the theme's own `const` and `define()` lines, none may start with `desktop_mode_`, and every `require_once` in `functions.php` must resolve; red against 13.4.0 both ways. #382.

### Changed
- **Core inlines the navigation stylesheet; the theme stops copying it and stops deferring a sheet core never links.** Two hand-rolls, one from March 2026 and one from July, sat on one symptom: `assets/css/critical.css` carried a verbatim copy of core's closed-state navigation rules (10.38.1, written against a nav request intermittently poisoned at the Cloudflare edge), and `inc/assets-frontend.php` rewrote the `wp-block-library` and `trp-language-switcher` link tags to `media='print' onload` through `style_loader_tag`, which core never reaches for either on a block theme (`wp-block-library` is registered with a src on a block theme, but core inlines it first: `wp_maybe_inline_styles()` runs at `wp_head` priority 1 and sets `src` to false on every sheet under the budget, so by the time `wp_print_styles` runs at priority 8, `WP_Styles::do_item()` returns at `if ( ! $src )` before the filter; live, `common.min.css` is 4,203 bytes and prints as `<style id="wp-block-library-inline-css">`; TranslatePress is gone from the site). Read `wp_maybe_inline_styles()` and the documented `styles_inline_size_limit` filter (core 5.8, default 40,000 bytes since 6.9): core inlines each block's sheet in `<head>`, smallest first, and breaks at the first overflow. Measured live on 2026-09-20: the home page inlines 23,363 bytes of block CSS, a Note 21,580, and the navigation sheet is 20,776, so it was the one sheet over the budget and the one that shipped as a render-blocking `<link>`. The theme now sets the budget to 64 KB with one filter line; every measured page inlines the nav, there is no nav request left for the edge to drop, and the copy (3,047 bytes off every page's inline critical block) and the dead deferral are deleted. Every declaration the copy carried was checked against core's live 7.1.1 sheet: all 23 are there. The one-line `color: inherit` on nav links (10.38.2) and the is-menu-open overlay (8.5.7) stay. `tests/styles-inline-size-limit.php` (12) runs the real registration through stubbed `add_filter`, calls the callback with core's default and pins the arithmetic against the measured sizes; 8 red against 13.4.0. `tests/nav-responsive-fallback.php` retires with the copy; `tests/cf7-removal.php` now pins that no `style_loader_tag` filter is registered at all, red on the old file. #385.

## [13.4.0] - 2026-09-20 — a tag files itself

### Added
- **A tag files itself: the Group field on Posts › Tags.** `/notes/tags` always read the vocabulary live; the one fact that was code was which of the four headings a tag sat under, so filing a new tag cost a theme release (13.3.3 was that release, for `fair-use`). The grouping now lives on the tag: `sn_tag_group` term meta (registered, in REST, sanitized to one of the four ids `record`, `settles`, `built`, `work`, or unfiled), a select beside the description on WordPress's own add and edit forms saved on `created_post_tag` and `edited_post_tag` behind the handler's own `edit_term` check and the tag form's nonce (the create hook fires from `wp_insert_term()` on every path that mints a tag, a Contributor's REST or `tax_input` create included, so relying on the form's gate would have let a Contributor file a tag under a heading; found in review), and a Group column on the tags list. The page files by meta first, then by the theme's slug lists, which stay as the seed for tags nobody has filed by hand; a tag in neither still shows under "Not yet filed", loud by design. The groups' titles and deks stay in the theme. `tests/notes-tags-group-meta.php` (19), `tests/notes-tags-index.php` (20).
