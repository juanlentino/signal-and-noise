# Changelog

All notable changes to the Signal & Noise theme are documented here.

This file holds two things only: **`## [Unreleased]`**, the working log that
accumulates across pull requests, and the **current release**. Everything older
lives in [docs/changelog/](docs/changelog/).

A pull request does not bump `Version` and does not tag — it closes an issue and
adds a bullet below. A release is a separate, deliberate act:
`tools/cut-release.sh`, which stamps `style.css` **and** `readme.txt` together.

## [Unreleased]

### New
- **The footer signs the site: stamp + wordmark + descriptor, once.** Convention for a personal site is the monogram alone in the header (the name is in the title, the H1 and the footer) and the full lockup where a site signs itself. `blocks/footer-signature` (the twelfth PHP-only block, `supports.multiple` false, the meta-nav precedent for SVG in a part) renders one home link: the JL stamp inline in `currentColor` at 28px (the canonical frame, `rect 6/6/188` stroke 12, mark at `translate(45 51.8) scale(0.753)` stroke 20) beside `Juan Lentino` in Bebas Neue at letter-spacing `wide` over `Producer / Mix engineer / Strategist` in DM Mono 500 at `ultra`, per `docs/BRAND.md`; text, not paths. It leads the footer bar before the social links, in the bar's `rust` with `blood` on hover like the meta-nav; the footer's height does not change (the 44px social icons still set it), and the descriptor drops under 480px. Pinned in `tests/footer-signature.php` (22): the geometry, the tokens, the single placement, the palette; `tests/blocks-php-only.php` counts twelve. Measured on the live page at 1440 and 375 before commit.

### Fixed
- **The wp-admin "Default OG image URL" setting works again; the brand card is the default, not an override.** 13.5.0's `sn_brand_og_image_default()` returned `assets/brand/og-image.png` unconditionally at priority 5, which made the plugin's Identity & SEO field a dead control: whatever the owner typed there was discarded before the plugin's own resolution ran. It now yields to a non-empty setting and fills in only when the field is blank (whitespace counts as blank), so the setting means what it says and clearing it gives the theme default. Singular views keep their generated cards and the `/notes` card still wins on the index, unchanged. `tests/notes-og-card.php` (+2) pins both branches; `tests/cross-package-listeners.php` Contract 7 pins a set value passing through and an empty one getting the card. Found by the owner on the day of the cut.
- **The SVG favicon draws its mark again.** 13.5.0's `assets/brand/favicon.svg` coloured the strokes with `stroke="var(--fg)"` from `:root` custom properties; Chrome's favicon renderer does not resolve `var()` in presentation attributes, so the tab showed the black ground with no mark (owner, 2026-09-21, the day of the cut). Colours are now class rules inside `<style>` (`.bg`/`.fg`, swapped under `prefers-color-scheme: dark`), the documented pattern for a scheme-aware SVG favicon; geometry unchanged. `tests/home-screen-icon-opacity.php` (+2) pins no `var(` in the file and the two colour pairs; 3 red on the shipped file.

### Changed
- **The five scaling presets are core `fluid { min, max }`, computed under the default viewport pair.** `xx-large`, `xxx-large`, `display-sm`, `display-md` and `display-lg` were hand-written `clamp(min, Xvw, max)` literals core never touched (13.4.1 measured why); each is now a bare `size` (the cap) plus `fluid: { min, max }` holding the old line's floor and cap, and core emits the clamp() (`clamp(3rem, 3rem + ((1vw - 0.2rem) * 4.444), 6rem)` for `xx-large`). `settings.typography.fluid` stays the bare `true`, the default 320px/1400px pair, by owner decision on 2026-09-21: the tuned pair the issue floated (680px/1370px) keeps the headings within ~4px of the old lines but re-scales the seven bare presets too, and `medium` is the global body size, `x-large` is h3 and `large` is h4, so it would have shrunk body copy by ~1.7px and h3/h4 by 4 to 5px at every tablet width on every page. Under the default pair the seven bare presets are byte-identical to what the site served on 2026-09-20 (section 1 of the suite is that guard); what moves is the five, between ~640 and ~1300px, larger: at 768px post h1 77 → 97px, post h2 54 → 68, note and page titles (`display-lg`) 46 → 57, pillar card titles 32 → 37, note card titles 29 → 33. Floor (320px) and cap (1440px) are identical to before. The editor's size picker now shows the computed clamps. `tests/fluid-type-presets.php` (74) pins the shape, the exact strings core emits and the px at 320/768/1024/1440 as a table; `tests/template-typography.php` pins the three display presets' `{ min, max }`; 28 red against the unported theme.json. #387.
- **The theme toggle is an Interactivity API store; its DOM binding is declared on the markup.** `assets/js/dark-mode-toggle.js` was a classic IIFE that queried every `.sn-theme-toggle`, bound a click handler to each and wrote `aria-pressed`, `aria-label` and the label text by hand on every change. It is now a plain ES module (`import { store } from '@wordpress/interactivity'`, served by core's import map, which the navigation block already loads on every page; no bundler) registering `signal-noise/theme-toggle` with `state.isDark`, `state.ready`, the derived `label` and `ariaLabel`, `actions.toggle` and `callbacks.init`; the three-state `localStorage` preference, the `matchMedia` follow-the-OS listener, `startViewTransition` and the theme-color sync (#333) move into it unchanged. `sn_dark_mode_toggle_markup()` carries the directives (`data-wp-interactive`, `data-wp-init`, `data-wp-on--click`, `data-wp-bind--hidden="!state.ready"`, `data-wp-bind--aria-pressed`, `data-wp-bind--aria-label`, `data-wp-text`) and sets the server state with `wp_interactivity_state()`: `isDark`/`ready` false plus the translated strings, because a null `data-wp-text` blanks the element and a null bind drops the attribute in the server pass. `blocks/theme-toggle/block.json` names `viewScriptModule` and `supports.interactivity`, so core processes the directives server-side and gives the module footer placement and `fetchpriority=low` itself; `inc/dark-mode.php` registers it with `wp_register_script_module()`. Two instances share one store by construction, so there is nothing to query and nothing to re-sync. Rendered bytes: the resting button is byte for byte what the IIFE shipped plus the directives, verified with core's own processor. Pinned: `tests/theme-toggle-directives.php` (23) runs WordPress 7.1's `WP_Interactivity_API` over the real markup and state (CI fetches the three `interactivity-api/` files beside the HTML API; `tests/lib/wp-html-api.php` loads them and carries core's `is_void()` list, the one static the processor needs from the full HTML Processor); the resting render, `hidden` surviving, the boolean-on-aria string, and the dark and light states the module reaches; red when a server string is missing. `tests/js/theme-toggle.test.cjs` (6) imports the real module under node against a stub `@wordpress/interactivity` (`tests/js/lib/`, resolved through `module.registerHooks`) and drives `init`/`toggle` through the blocked-storage, stored-light, stored-dark and no-choice scenarios; `tests/dark-mode-chrome-sync.php` (#333) drives the same store; `tests/block-view-scripts.php` and `tests/dark-mode.php` re-pinned. Closes #384.
- **The header mark is 64px, with one stroke of clear space.** 13.5.0 sized the inline mark to the old raster's 80px BOX; the glyph inside that box was smaller, so the mark shipped visibly larger than the logo had ever appeared and heavier than the nav. It is 64px now (stroke 10px, still Bebas weight), 40 scrolled, 48/32 and 36/28 at the two breakpoints, all above the 16px floor. `.sn-logo-link` gains `padding-block: 0.25rem`: `docs/BRAND.md` asks one stroke width of clear space and the header's 0.44rem padding gave 7px of the 10. The header is 7 + 4 + 64 + 4 + 7 = 86px (was 94), so `body` padding-top goes 108 → 100 and `scroll-padding-top` 124 → 116, keeping the 14px gap; the two lower breakpoints land on their previous header heights exactly (48 + 8 = 56, 36 + 8 = 44), so their offsets do not move. `article-toc.js` measures the header live and its comment is corrected. `tests/footer-signature.php` derives the body offset from the header arithmetic and reads the clear space against the stroke; 5 red on the 13.5.0 CSS. Measured on the live page: header 86px, mark at y=11.

## [13.5.0] - 2026-09-21 — the JL mark

### Fixed
- **The header logo renders again, and it no longer depends on an upload.** `parts/header.html` hardcoded `<img src="/wp-content/uploads/2026/09/cropped-jl_logo-min-150x150.webp">`, a specific attachment thumbnail; the file stopped resolving (`naturalWidth === 0`) and nothing in the theme, in wp-admin, or in any cache purge could repair a string pointing at a missing upload. The header now carries the JL mark inline as SVG (`viewBox 0 0 146 128`, stroke 20, `stroke="currentColor"`) inside the home link (`aria-label="Juan Lentino — home"`, the SVG `aria-hidden`), so there is no logo request at all. The mark is inked with `bone`, the token the dark layer already flips, so one declaration covers both schemes and the `--sn-mark-invert` filter token and its `invert()` rule are gone with the raster. It keeps the exact heights the image had (80/48, 56/38, 44/34 across the header states and breakpoints, all above the 16px floor) so the header height, and `body` padding-top, `scroll-padding-top` and `article-toc.js`'s offsets keyed to it, do not move; width follows the viewBox and is never set alone. Pinned in `tests/brand-mark.php` (12): inline SVG with the canonical geometry, one accessible name, no `<img>` or uploads URL, zero `cropped-jl_logo` references across the theme, every `.jl-mark` height at or above 16px, no fixed width, the `bone` ink and no second dark rule; 6 red against the old part.

### Changed
- **One icon set, from `assets/brand/`.** `inc/dark-mode.php` emits `favicon.svg` (the JL tile; it carries its own `prefers-color-scheme` rule and inverts with the OS), `favicon.ico` (`sizes="any"` fallback) and one opaque 180px `apple-touch-icon.png`, in that order, and the light/dark PNG pairs (`favicon-32*`, `app-icon-180*`) go with the `jl-logo-*` and `app-icon-192/512` rasters nothing referenced. Core's `site_icon_meta_tags` are now removed wholesale (`__return_empty_array`) rather than only the apple-touch-icon: `wp_site_icon()` runs at `wp_head:99`, after the theme's block at 1, and with `icon-512.png` set as the Site Icon it would have printed a second, competing favicon set; the uploaded Site Icon still serves wp-admin, the login screen and the manifest, which read it directly. `assets/js/dark-mode-toggle.js` stops rewriting favicon `href`s on toggle: the SVG inverts by itself, and the old pair-swap run against the new head wrote the `.ico`'s href onto the SVG link (`tests/dark-mode-chrome-sync.php` goes red on the old script for exactly that). The reader-toggle-against-OS case now updates `theme-color` only; the tab icon follows the OS, which the brief accepts. `tests/head-sweep.php` pins the single-set shape and the SVG-before-ico order; `tests/home-screen-icon-opacity.php` pins both brand PNGs opaque (colour type 2) and the wholesale filter (red on `__return_false`).
- **The site-default `og:image` is the 1200x630 JL card.** The companion plugin seeds `sn_og_image_url` with the wp-admin "Default OG image URL" setting (a small square logo); `inc/notes-og-card.php` now replaces that seed at priority 5 with `assets/brand/og-image.png`, before the plugin's per-post cards (10) and the `/notes` card (20), so singular views are unchanged and home, archives and search preview with the card. The plugin already declares `twitter:card=summary_large_image` and `twitter:image` from the same value. `og-image.png` was re-rendered headlessly from `og-image.html` with the theme's own `dm-mono-400/500-latin.woff2` (the shipped PNG used a substitute monospace); the template's `@font-face` points at `assets/fonts/` and documents the render command. `tests/notes-og-card.php` (+4) and `tests/cross-package-listeners.php` Contract 7 pin the new default.
- **Buttons are square.** `theme.json` `styles.elements.button.border.radius` was `999px`, a pill, against the README's "no rounded corners"; it is `0`. The sweep of `assets/css`, `blocks/`, `patterns/` and `styles/` found four other non-zero radii and left all of them, each deliberate: `50%` on three true circles (`.sn-disco-play-circle`, the 7px `.sn-music-featured__dot` and `.sn-availability__dot`) and `--sn-spotify-radius: 12px`, documented in place as matching Spotify's own embed chrome.
