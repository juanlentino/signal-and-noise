# Changelog

All notable changes to the Signal & Noise theme are documented here.

This file holds two things only: **`## [Unreleased]`**, the working log that
accumulates across pull requests, and the **current release**. Everything older
lives in [docs/changelog/](docs/changelog/).

A pull request does not bump `Version` and does not tag — it closes an issue and
adds a bullet below. A release is a separate, deliberate act:
`tools/cut-release.sh`, which stamps `style.css` **and** `readme.txt` together.

## [Unreleased]

### Fixed
- **The theme's own Copilot tool-schema normalizer was a hand-rolled twin of OpenStation's `openstation_ai_normalize_tool_schema()`, registered on a hook name OpenStation dropped at v1.0.0.** `inc/desktop-mode-copilot-schema.php` hooked `desktop_mode_ai_tools` alone, so on every release the site has run since August it never fired, while its docblock and the `functions.php` require line promised a guard the theme did not provide. Read: OpenStation's `docs/hooks-reference.md` names `openstation_ai_tools` as the Stable tool-list filter, and `includes/ai-copilot/search.php` at v1.1.10 normalizes every tool schema itself after that filter (the union top-level `type`, top-level `anyOf`/`oneOf`/`allOf`, empty `properties`, idempotent), which is the converter the module's docblock said should own this. Upstream has done this since v0.9.6 (2026-07-23, upstream #366, the fix for #362; the `openstation_` name since v1.0.0), one week after the theme's module was born in 10.42.3 citing that same #362, so the module was redundant on every release but the first week and dead by name on every release since August. The module, its require line, its file-map row and `tests/desktop-mode-copilot-schema.php` are deleted; the three shapes the theme declares are untouched and now pinned in `tests/abilities-registration.php` (+3: the top-level `anyOf`, the `object|null` union type, the empty `properties`). Nothing on screen changes: the module filtered an admin request the Copilot builds, never public output, and on the live site (OpenStation 1.1.10, companion plugin active) it was not running at all. Pinned by derivation in `tests/openstation-hook-names.php` (7): every hook name the theme registers or fires is read off the source with `token_get_all()` (a regex stripper opened a comment on the `styles/*.json` inside a description string and swallowed 225 lines of `inc/abilities-diagnostics.php`; found in review), a constant first argument resolves through the theme's own `const` and `define()` lines, none may start with `desktop_mode_`, and every `require_once` in `functions.php` must resolve; red against 13.4.0 both ways. #382.

Changed: `blocks/suggestions-404` (`block.json` with `supports.autoRegister`, core since 7.0; `render.php` calling `sn_404_suggestions_shortcode()` through `sn_php_block_output()`, the same `wpautop()` wrapper as the nine), the slug in `sn_php_only_block_slugs()` and the editor palette, `<!-- wp:signal-noise/suggestions-404 /-->` in the template (a block name must start with a letter: core's parser and the JS registration both refuse `404-suggestions`, and `tests/blocks-registry.php` now pins every manifest name against that rule), and the bridge removed from `inc/404-recovery.php`. Pinned: `tests/404-recovery.php` runs core's real `wpautop()` (`tests/lib/wp-autop.php`, copied verbatim from 7.1) over the block's render and compares it with the bytes the old template path produced, captured from the pre-swap code, byte for byte; `tests/blocks-php-only.php` counts ten blocks, the parity pair, the template placement, no `wp:shortcode` left in `404.html`, the palette. Changed: each manifest names its handle (`sn-note-share`, `sn-contact-aliases`, `sn-dark-mode-toggle`), each module registers that handle at `init` with the arguments its enqueue used to pass, and the three `wp_enqueue_scripts` gates are gone; the `/contact` enqueue of the shared alias handle stays, that page is not a block. And reach: `templates/single.html` is the only include of `parts/post-closing.html` and there is no `attachment.html`, so every singular that falls to `single.html` without being a `post` (attachment pages today) prints `note-share.js` and `contact-aliases.js` where the old `is_singular( 'post' )` gates did not; both scripts querySelectorAll their row and no-op without it, so the page behaves as before, and whether attachment pages stay enabled (`wp_attachment_pages_enabled`) is the owner's question, not this cut's. The Interactivity API rewrite of the toggle's state is the issue's named second step and is not in this cut: it changes the toggle's public markup (directives, and a server state block, since the server-side directive processor removes a `data-wp-bind` attribute and blanks a `data-wp-text` that evaluate to null), and three harnesses still run `dark-mode-toggle.js` as a bare script. `tests/block-view-scripts.php` (35) pins the manifests, the registrations against origin/main's captured enqueue arguments, that no gate enqueues the three handles on a single note, with a sibling gated handle and the `/contact` enqueue as controls, and the template shape the attachment reading rests on; 26 red against the unfixed code. #384.
- **Five hand-written `clamp()` presets measured against core's `fluid: { min, max }`, and the three inert opt-outs removed.** `theme.json` sets `typography.fluid` on and then hand-writes `clamp(min, Xvw, max)` on `xx-large`, `xxx-large`, `display-sm`, `display-md` and `display-lg`; the native shape is a bare size plus a `fluid` object, computed by core from one global viewport pair. Read `wp_get_typography_font_size_value()` and `wp_get_computed_fluid_typography_value()` in WordPress 7.1 and drove them, not a re-derivation: core draws a line from `(minViewportWidth, min)` to `(maxViewportWidth, max)`, a hand-written `Xvw` is a line through the origin, and the two coincide only at that preset's own floor and cap crossing, which differs for each of the five. Under today's effective pair (320px to 1400px) every one of the five renders differently at 768 and 1024, and any other pair reproduces at most one of them while rewriting the seven bare presets core already fluidises. So none ports and all five stay literal; the pair is the owner's call (#387 names it). What changed: the `"fluid": false` beside the three `display-*` clamps was inert (core returns a `clamp()` size verbatim either way) and is gone, byte-identical output. Pinned in `tests/fluid-type-presets.php` (73): a verbatim copy of core's `block-supports/typography.php` as the fixture, the seven bare presets equal to the strings the live site emitted on 2026-09-20, the exact `clamp()` core would emit for each of the five with the px at 320, 768, 1024 and 1440 beside the hand-written line, and the two own-crossing pairs proving one preset per pair. A red on one "differs" line is a crossing at that width, not a match; the port signal is the per-preset "every tested width" line, red when a port would render the same px at 320, 768, 1024 and 1440 (never byte-identical: core's middle term is `min + ((1vw - offset) * factor)`, the hand line is `Xvw`). #387.

## [13.4.0] - 2026-09-20 — a tag files itself

### Added
- **A tag files itself: the Group field on Posts › Tags.** `/notes/tags` always read the vocabulary live; the one fact that was code was which of the four headings a tag sat under, so filing a new tag cost a theme release (13.3.3 was that release, for `fair-use`). The grouping now lives on the tag: `sn_tag_group` term meta (registered, in REST, sanitized to one of the four ids `record`, `settles`, `built`, `work`, or unfiled), a select beside the description on WordPress's own add and edit forms saved on `created_post_tag` and `edited_post_tag` behind the handler's own `edit_term` check and the tag form's nonce (the create hook fires from `wp_insert_term()` on every path that mints a tag, a Contributor's REST or `tax_input` create included, so relying on the form's gate would have let a Contributor file a tag under a heading; found in review), and a Group column on the tags list. The page files by meta first, then by the theme's slug lists, which stay as the seed for tags nobody has filed by hand; a tag in neither still shows under "Not yet filed", loud by design. The groups' titles and deks stay in the theme. `tests/notes-tags-group-meta.php` (19), `tests/notes-tags-index.php` (20).
