# Changelog

All notable changes to the Signal & Noise theme are documented here.

This file holds two things only: **`## [Unreleased]`**, the working log that
accumulates across pull requests, and the **current release**. Everything older
lives in [docs/changelog/](docs/changelog/).

A pull request does not bump `Version` and does not tag — it closes an issue and
adds a bullet below. A release is a separate, deliberate act:
`tools/cut-release.sh`, which stamps `style.css` **and** `readme.txt` together.

## [Unreleased]

### Changed
- **/stats sits on the site's split hero.** It used `page.html`: an 80px title, a rule, then the stats, the one page title off the site's scale. Its own template, `templates/page-stats.html`, puts the page title on the left at the site title scale (the post-title block at `pageHeadline`, `clamp(3rem, 8vw, 7rem)`, still editable and still carrying its view-transition name) and two lines on the right, approved word for word by the owner: "What gets read here, counted at the edge without cookies." and "How it's measured", which links to the method paragraph the plugin renders with `id="sn-public-stats-method"`. The band has no width of its own: the plugin's /stats stylesheet widens main's children to the page track, as it did the old title, so hero and stats measure 1320px wide at 1440px like every other hero. The title's line height is the `flat` token (1); the other heroes set 0.95 as a literal, which a template may not, so a two-line title would sit 5% looser. Registered in `theme.json` for pages, titled "Stats". Core's block parser reads the template as exactly the intended tree. `tests/page-stats-template.php` pins it; the width and typography guards cover it like every template.
- **One fullscreen attribute per Spotify frame.** The featured player and the discography's click-to-play frame said fullscreen twice, in `allow` and in the legacy `allowfullscreen`, and the browser warns that `allow` wins. `allowfullscreen` is gone from both; `allow` still grants fullscreen.
- **The text-spacing audit is on record.** `docs/ACCESSIBILITY.md` records the 2026-10-31 WCAG 1.4.12 audit: nine pages at two widths passed, what the detector checked and what it did not.

### Added
- **A copy-link button beside each section heading of a note.** On every note with a Contents card (three or more sections), each H2 the card names carries a small `#` button that copies the note's canonical address with that section's id (the page's own address when the canonical is on another host, as for a republished note), shows COPIED for 1.6 s as a small label above the `#` (out of flow, so the heading never reflows on a phone) and announces "Link to section copied" through a live region that is in place before the first copy (or COPY FAILED and "Copy failed"). Its accessible name is "Copy link to section: <heading>", and the heading keeps its own text as its name, so a screen reader's list of headings does not also read the button. The button is drawn by `assets/js/article-toc.js`, never by the server: copying needs script, so feeds, the Markdown and JSON twins and readers without script never meet a dead button, and the in-browser verifier, which hashes the signed payload rather than the page, is untouched. 11px label type, a 24px target, never selected with the heading text (Safari included), hidden in print. The clipboard and the announcement now come from one helper, `assets/js/sn-copy.js` (`window.snCopy`, registered by `inc/sn-copy.php`), which the share row also uses instead of its own copy. `tests/js/section-links.test.cjs` drives the real scripts; `tests/block-view-scripts.php` pins both dependencies and `tests/print-styles.php` the print hide. Twenty-two mutants that change what a reader gets were seen to fail their test, twelve of them added after review (`tests/section-link-css.php` pins the CSS the button promises).

### Fixed
- **The printed record says which clock its date reads.** The print colophon's "recorded" date was site time (US Eastern) with no label, so a version committed in the evening printed the day before the date the provenance panel gives it in UTC. It now prints the UTC date and says so ("recorded October 16, 2026 UTC"). The post date and the Updated line stay site time, which is why the label is there. `tests/print-colophon.php` stubs `wp_date()` in site time as the live site runs it, so the pin can tell the two apart.
- **The search palette and the shortcut sheet are native modal dialogs.** Both were a `<div role="dialog" aria-modal="true">`, which leaves the page behind reachable: VoiceOver in Safari does not honor `aria-modal`, so its cursor could walk out of the overlay. Each is now a `<dialog>` opened with `showModal()`, so the page behind is inert (a header link cannot take focus while either is open) and the overlay sits in the top layer. Everything readers use stays: the same look (the UA dialog box is reset to the old full-viewport overlay, and the dimming stays on the existing backdrop), the Tab trap, Escape, the backdrop click, the IME guard, and focus back on the opener. A close the browser makes itself (Escape's cancel, Android back) now runs the scripts' own close through the dialog's `close` event, so they never think a closed dialog is open. Checked in Chromium, Firefox and WebKit on a real note page: the palette renders pixel-identical to before in light, dark, forced colors and more contrast at four viewport sizes; the page behind refuses focus; Tab stays on the input or the switch; Escape and a backdrop click close and return focus. Review found, and this fixes before it shipped: with the focus now synchronous, a real `?` (Shift+/, which also reports keyCode 191) opened the palette and left the shortcut sheet, which holds the WCAG 2.1.4 switch, unreachable; the palette now reads keyCode only when `key` is missing. A close event arriving after a quick reopen no longer closes the new session, and the sheet's panel takes focus first in every engine (`autofocus`). `tests/js/native-dialog.test.cjs` pins the element, `showModal()`, no ARIA stand-in, the browser-made close, a real `?` with both scripts on one page, and a late close event; `tests/command-palette.php` and `tests/keyboard-nav.php` pin that a closed dialog is `display: none` (the overlays' `display: flex` would otherwise cover the page).
- **One single-key shortcut switch for the palette and the note shortcuts.** The search palette (`command-palette.js`, every page) and the note shortcuts (`keyboard-nav.js`, j, k and ?) each kept a verbatim copy of the form-field guard and of the WCAG 2.1.4 switch, including a separate in-page memo. With browser storage blocked, turning the keys off in the palette left j and k on. Both now take the guard and the switch from one helper, `assets/js/sn-keys.js` (`window.snKeys`), registered once (`inc/sn-keys.php`) as a dependency of both scripts: one small deferred file. `tests/js/single-key-shortcuts.test.cjs` pins the shared switch with storage throwing (it failed on the old copies); the PHP suites pin that neither script keeps a copy and that both depend on `sn-keys`.

### Changed
- **The theme's update check rides WordPress's own Update URI hook.** `style.css` names the repository in `Update URI:`, and core's `wp_update_themes()` asks `update_themes_github.com` for it once per check, then files the answer under "update available" or "up to date" itself. The theme used to rebuild that entry on every write of the `update_themes` record instead (`pre_set_site_transient_update_themes`, two writes per check). The new `sn_gh_theme_update_offer()` returns the latest GitHub tag as the version, with the same package and details URL; any other theme whose Update URI is on github.com passes through untouched. Check Again (`?force-check=1`, still gated on `update_themes`) still bypasses the cached tag, and the read-time guard that never offers the installed version is unchanged. One difference: core skips the hook when its WordPress.org request fails. A recorded entry then stays; if the record was just cleared (after an install, or a cache purge), the theme is absent until the next direct check (the Themes or Updates screen, or the cron), which re-runs at once. `tests/updater-github-auth.php` pins the registration (including the three arguments the offer needs, without which it answers no theme), that the hook's host is the Update URI's, that nothing rebuilds the record on write, the offer itself, the pass-through, the forced check, an ordinary check reading the cached tag, and the no-tag case; each pin was seen to fail with its guard removed.
- **`components.css` is its 20 ordered parts (code health, no visual change).** The 2,523-line file was cut at top-level rule boundaries only into `assets/css/components-01-pages-base.css` through `components-20-essay.css`, each a component's own rules (discography, 404, theme toggle, essay and so on). Joined in order the parts are byte-identical to the old file (SHA-256 `397078b4…` both ways), and `inc/components-css.php` holds the one ordered list every consumer reads: the combined bundle minifies them as ONE unit under one label, so the served stylesheet is the old one with a single label line changed; the per-file fallback enqueues each part on the one before, the last as `sn-components`, which every other sheet already depends on; the editor loads them where `components.css` stood. They sit at the top of `assets/css/` (not a subfolder) so every existing test that scans `assets/css/*.css` keeps covering them. Tests that pinned a rule in `components.css` read the joined layer (`tests/lib/components-source.php`); `tests/components-split.php` pins the list against the disk, the numeric order, each consumer's position and that every part opens and closes its own blocks, and fails on an unlisted part, a swapped order or a cut inside a block.
- **Four oversized theme files are split into smaller ones, the code moved verbatim (no behavior change).** `inc/abilities-diagnostics.php` (1,021 lines), `inc/abilities-ai-generation.php` (693), `inc/wp-update-integration.php` (739) and `inc/notes-index-helpers.php` (613) are now thin loaders that `require_once` 29 parts beside them (`inc/<name>-<part>.php`) in the original order, so `functions.php` and every test that loads the old paths are unchanged. 57 functions, 25 hook and ability-registration calls and 10 constants moved token for token, docblocks included. The two ability registration functions stay whole (386 and 267 lines), since splitting a function body is not a move. The PHPStan baseline follows the five `snt_ai_generate_with_constraints` calls to their new files, three source-pinning tests read the part that holds their snippet, and `tests/updater-github-auth.php` reads the whole module, since one of its pins asserts an absence.

### Fixed
- **The note-link preview card can be hovered (WCAG 1.4.13).** Leaving a note link removed its card at once, and the card was `pointer-events: none`, so a reader could not move onto it, to magnify or re-read it, without it disappearing (verified live 2026-10-31). Leaving the link now starts a 300 ms grace, moving onto the card cancels it, leaving the card starts it again, and returning to the same link keeps the same card. Only the link itself and the card itself count: the pointer moving between the card's lines and its padding, or between a link's `<em>` and its text, is not leaving (pointerenter and pointerleave fire on every element crossed). The grace removes the card only, so reaching another link inside it still shows that link's card. Escape, blur and the 120 ms intent delay are unchanged; phones never get the card. Pinned by the first behavior test for `assets/js/note-link-previews.js` (`tests/js/note-link-previews-hoverable.test.cjs`, which drives the real file).
- **Smoke Test fetches the stylesheet the pages link (CI).** A page could answer 200 while the `sn-styles-<hash>.css` it names 404s (2026-09-17), and every HTML check passed while the site rendered unstyled. The smoke job now reads the home page's combined stylesheet and requires a 200 with `text/css`; a page that links no combined sheet, or an edge block (403, 415, 429, as everywhere else in the job), is a warning. One more step in the existing job.
- **The two live checks measure again (CI).** Smoke Test had failed every run since 2026-10-12 (about 400 in a row), the day the `note-markdown` surface joined agents.json: it probed the surface at its advertised url, `/notes/`, which is the HTML archive, while the surface is a convention (`/notes/<slug>.md`), like `content-json`. It now probes the newest note's own advertised `.md` twin (the feed names the note, its head names the twin, both fetches retried like every probe) through the normal check: 200 and a Markdown content type. A note whose head names no twin fails, with the response shown. Contrast (live) had died before measuring since 2026-10-18: the site's hash-only script-src blocked the measuring tool, injected as an inline script. It is now evaluated instead, which script-src does not govern, so the measured pages keep the CSP readers get.
- **Dependabot resolves composer again (dev tooling).** `roave/security-advisories` now conflicts with PHP 8.3 below 8.3.36, and Dependabot resolved against a bare 8.3 (`php is present at version 8.3`), so every composer update failed. `config.platform.php` is 8.3.36, the patched release of the line CI runs. When roave raises the 8.3 floor past it, bump the pin: Dependabot will not.

### Removed
- **Code nothing runs or renders.** The `script_module_loader_tag` filter in `inc/assets-frontend.php` (WordPress 7.1 has no such filter; core already gives these modules `fetchpriority="low"`). Four CSS blocks no template, pattern, script or published or scheduled note emits: `.sn-process-strip` (components and responsive), `.sn-note-meta-divider`, `.sn-catalog-meta-bullet`, and the sub-pillar "Extended by" backlink `.sn-provenance-extended-by` with `tests/provenance-extended-by.php`, which pinned only that CSS (the sub-pillars are gone). `.sn-credibility-strip` stays until the plugin's seed content that still carries it is retired.
- **The `sn-notes-build` marker.** `wp_footer` printed it on every page whichever renderer ran, and it had not changed since 2026-06-05, so it proved nothing. `docs/WORDPRESS-REFERENCE.md` now checks the live renderer by `sn-notes-headline`, a class only the PHP renderer prints.

### Fixed
- **A failed copy right after a successful one no longer stays drawn as a success.** On a note's share row, COPY LINK that succeeded and then failed within 1.6 s showed COPY FAILED, then COPY LINK, in the filled red "copied" style until some later copy succeeded: the failure path restored the label but not the class. It now drops the style at once. Found by the new note-share tests and pinned there.
- **Cmd-click, Ctrl-click, Shift-click and Alt-click on a note's contents links do what the browser does.** The contents list took every click to scroll this page, so a reader could not open a section in a new tab or window. A modified click is now left to the browser; a plain click still scrolls, focuses and sets the hash.

### Tests
- **Behavior tests for four front-end scripts that had none (code health).** Each drives the real file under a fake DOM built from the markup the PHP side prints, in the existing `node --test tests/js/*.test.cjs` step. `discography.test.cjs`: role chips filter the grid, collapse empty years, update the count, the empty state, `aria-pressed` and `?role=` (an unknown role falls back to All); no Spotify iframe ships and a cover mounts its embed only when played, by click, Enter or Space; liner-notes previews share one `<audio>`, and A's late `play()` rejection never stops B (#325). `article-toc.test.cjs`: a contents click scrolls (instant under reduced motion), focuses without a second jump and sets the hash; a missing heading, a bare `#` or a note without a TOC is left to the browser. `note-share.test.cjs`: COPY through the Clipboard API or the textarea fallback, COPIED or COPY FAILED and back after 1.6 s, the polite live-region announcement, and SHARE revealed only where Web Share exists. `contact-aliases.test.cjs`: base64 parts become the mailto link, a UTF-8 subject survives `rawurlencode` and back (#328), and a malformed or hostile span keeps its fallback without stopping the rest. The discography fake is in `tests/js/lib/fake-dom.cjs`; the other three keep their own small fakes. 28 mutants that change what a reader sees were seen to fail their test (20 at first, 8 more after review: Back pushing history, the empty state staying shown, a playing preview without its playing style, the embed's class, title and `allow`, a fallback copy that never selects, and a failure that does not restart the 1.6 s).
