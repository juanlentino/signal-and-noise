# Changelog

All notable changes to the Signal & Noise theme are documented here.

This file holds two things only: **`## [Unreleased]`**, the working log that
accumulates across pull requests, and the **current release**. Everything older
lives in [docs/changelog/](docs/changelog/).

A pull request does not bump `Version` and does not tag — it closes an issue and
adds a bullet below. A release is a separate, deliberate act:
`tools/cut-release.sh`, which stamps `style.css` **and** `readme.txt` together.

## [Unreleased]

### Changed
- **Each AI ability's `tokens_used` now says what it is.** The output schema of all five generative abilities describes the figure as an output-only estimate (characters / 4) that leaves out the prompt. The field keeps its name, so nothing that reads it breaks. Test: `tests/ai-tokens-used-schema.php`.
- **The /notes summary ability runs on the official AI plugin when it can.** `signal-and-noise/ai-generate-page-note-summary` keeps its name and its `{summary, post_id, tokens_used}` answer, but when the AI plugin registers `ai/summarization` it now runs that ability for the post, with the /notes voice and the word cap appended to the official instruction for that one call. An error from the official ability is returned as is. Without the AI plugin, the theme's own path runs as before. Test: `tests/ai-note-summary-official.php`.
- **The essay tracklist and the résumé lanes read the stored content with the HTML API.** `sn_essay_tracks()` and `sn_resume_lane_axis_start()` walk the markup with `WP_HTML_Tag_Processor` instead of regular expressions. On block-built essays and résumés the output is the same. Three cases the regex got wrong now work: a rail with a single-quoted class, a date written with an encoded en dash, and an HTML comment between a "Section N" label and its heading. Tests: `tests/essay-tracklist.php`, `tests/surface-lanes.php`.
- **The provenance brow finds its place with the HTML API.** `sn_prov_brow_is_eyebrow()` and `sn_prov_brow_content_has_eyebrow()` look for a P element carrying `sn-catalog-eyebrow` or `sn-provenance-eyebrow` with `WP_HTML_Tag_Processor`, not a regular expression. A single-quoted or unquoted class now counts, and a page that only mentions the class in text or a comment no longer stops the badge from being placed. The output markup is unchanged. Test: `tests/provenance-brow-badge.php`.
- **The header logo is core's Site Title block.** `parts/header.html` places `core/site-title` (a P wrapper, `isLink`) instead of a hand-written anchor, so the name follows Settings > General and the link follows `home_url()`. `inc/site-title-logo.php` adds the `sn-wordmark` class and the same accessible name with the HTML API, and on a Spanish page sends the link to the Spanish home with the Spanish label. The wordmark looks the same: the wrapper keeps `sn-logo-link` and the link carries `sn-wordmark`. On the front page the link now also carries core's `aria-current="page"`. Test: `tests/site-title-logo.php`.
- **The Spanish header and footer strings are set with the HTML API.** `sn_lang_chrome_strings()` and `sn_lang_meta_nav()` find the menu's labels, the search trigger's word and each footer link (by its href) with `WP_HTML_Tag_Processor` instead of matching exact bytes, so a reordered attribute, an added class or a resave in the editor no longer stops the translation. The Spanish text is the same. English pages are untouched. Test: `tests/lang-chrome.php`.
- **`/llms-full.txt` summarizes each note with core's excerpt.** A note without a manual excerpt is summarized from `get_the_excerpt()` (shortcodes and the blocks core leaves out of an excerpt are dropped), trimmed to 28 words and decoded for plain text, instead of from raw `post_content`. The password gate on the query and the per-row check both stay, and a test now proves a protected note never reaches the file. Some summaries read differently. Test: `tests/llms-txt.php`.
- **The purge probe reads the render-epoch tag with the HTML API.** `sn_purge_probe()` finds `<meta name="sn-render-epoch">` with `WP_HTML_Tag_Processor`, so a minifier or edge rewrite that reorders or unquotes the attributes no longer turns a fresh page into "unknown". A non-digit value is still unknown, never a pass. Test: `tests/purge-verify.php`.
- **The speculation module's header says what core does in 7.1.** Core sets mode and eagerness to `auto`, which resolves to prefetch and conservative unless the host sets the `WP_SPECULATIVE_LOADING_DEFAULT_*` constants; the theme's explicit prerender and moderate take precedence over both. A comment change only.
- **Core's Site Icon prints again, with the theme's SVG first.** The theme no longer empties `site_icon_meta_tags`. When a Site Icon is set in Settings, core prints its PNG sizes and apple-touch-icon and the theme puts its versioned `favicon.svg` at the front of that list. When none is set, core prints nothing, so the theme prints its own SVG, .ico and opaque apple-touch-icon as before. Test: `tests/site-icon.php`.
- **The Pull-quote pattern is core's Pullquote block.** `patterns/pull-quote.php` keeps its slug and now inserts `core/pullquote` with the Pull-quote style instead of a group of two classed paragraphs. The editorial conventions registry names the new selector. Test: `tests/pullquote-core-style.php`.
- **The pillar-essays and sidenote block stylesheets name the font presets.** The nine retyped stacks are now `var(--wp--preset--font-family--body)` and `var(--wp--preset--font-family--heading)`, which resolve to the same fonts. Test: `tests/block-css-font-presets.php`.
- **Reading time is core's Time to Read block.** The note front matter and the note cards on the Notes index place `core/post-time-to-read` with the classes, colors and spacing the bound paragraphs had. `inc/post-time-to-read.php` writes the plugin's figure into it, worded "N min read" as before, so it still matches the byline and the schema; without the plugin, core's own "N minutes" shows. The element is now a `div` with `wp-block-post-time-to-read`. The `reading_time` binding key is gone. The pillar cards keep their `[sn_reading_time slug]` shortcode: core cannot target a post by slug outside a query. Test: `tests/post-time-to-read.php`.
- **The 404 notes search is core's Search block.** `templates/404.html` places `core/search` (a `<search>` landmark, hidden "Search notes" label, "Search" button) instead of a hand-written form. `inc/search-404.php` keeps the form submitting to `/notes/`, where the theme answers `?s=`, puts the theme's classes on the field and button, and drops core's element-button class so theme.json's button padding does not restyle it. The field is now `required`, so an empty search is not sent. Test: `tests/search-404.php`.
- **The skip link is core's.** The theme no longer prints its own `.sn-skip-link` on `wp_body_open` or hides core's `#wp-skip-link`. Core inserts its link first in the page and points it at the template's `<main>`; `critical.css` keeps it hidden until it has keyboard focus, then shows it as the panel (panel colors, the heading face, the blood outline), the same look as before. The three pages that render from PHP rather than a block template (`/notes/`, `/index/`, the tag pages) print the same core markup right after `wp_body_open()`, so no page is left without one. The link text is now core's translatable "Skip to content". Tests: `tests/frontend-filters.php`, `tests/style-variations.php`.
- **The inline CSS and the theme-init script go through core's inline APIs.** `critical.css` and the hero pulse rule are src-less style handles with `wp_add_inline_style()`, printed by handle at the same `wp_head` priorities (50 and 51), so their place in `<head>` does not move; their ids are now `sn-critical-inline-css` and `sn-hero-pulse-inline-css`. `#sn-theme-init` is printed with `wp_print_inline_script_tag()`, so `wp_inline_script_attributes` sees it. Core wraps the script in the same newlines the hand-written tag had, so its bytes, and its CSP hash `sha256-+aDIk0AQYDEK+tK47t/wNITT4nprLRPhL+LH2Hb8THs=`, are unchanged. Tests: `tests/theme-init-csp-hash.php` (through core's real function), `tests/head-sweep.php`, `tests/hero-pulse.php`.

### Added
- **The machine files are registered with the rewrite API.** `inc/machine-routes.php` adds a rewrite rule and the `sn_machine` query var for `/opensearch.xml`, `/humans.txt`, `/.well-known/security.txt`, `/llms.txt` and `/llms-full.txt`, the way core registers `robots.txt`, so WordPress resolves them as routes instead of 404s. The same `template_redirect` handlers answer them, after `send_headers` and `wp` have run. The rules take effect at the plugin's next rewrite flush; the theme does not flush. Until that flush is confirmed live, the `REQUEST_URI` handlers, their `status_header( 200 )` and the 404-header undo in `cache-headers-hooks.php` stay as the fallback. Test: `tests/machine-routes.php`.
- **A Pull-quote style for core's Pullquote block.** `styles/blocks/pull-quote.json` registers `is-style-pull-quote` on `core/pullquote`, and the `article.css` rules that draw `.sn-pull-quote` (the rules, the ground, the bleed, the italic body and the mono attribution) now draw it too. The editor offers it as a variation and offers a one-step transform from the custom block. The custom `signal-noise/pull-quote` block stays registered with the same render, so anything written with it looks the same, but it leaves the inserter. No stored content is changed. Test: `tests/pullquote-core-style.php`.

### Removed
- **The hand-printed Bebas Neue `@font-face` (`<style id="sn-critical-fonts">`).** Core already prints the same face from `theme.json` through `wp_print_font_faces()` in `<head>`, at the URL the theme preloads. The two font preloads stay. Test: `tests/head-sweep.php`.
- **`a:focus-visible` and `.wp-block-button__link:focus-visible` from the global focus rule in `base.css`.** `theme.json`'s link and button elements already draw the same 2px blood ring at a 3px offset. The rule keeps bare buttons, ARIA roles, checkable and submit inputs, and `summary`, which those selectors do not reach. Nothing visible changes. Test: `tests/theme-json-elements.php`.
- **The third copy of `.screen-reader-text`, in `notes.css`.** `critical.css` is inlined on `/notes/` too, and its copy matches core (`clip-path`, with the focus reveal). The `critical.css` comment now names where core ships the utility: block-library's `common.css` and the `wp-block-template-skip-link` stylesheet. Test: `tests/screen-reader-text-critical.php`.
