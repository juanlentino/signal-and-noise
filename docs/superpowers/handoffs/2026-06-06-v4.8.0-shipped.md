## ⭐ TOP: what shipped — plugin **v4.8.0** (on `main`, tagged `v4.8.0`, commit `aa860de`)

Two workstreams in one minor, built brainstorm → spec → plan → one-implementer (TDD) → adversarial review → fix → ship:

- **A. Sidebar cleanup (dedupe `ai/ai`).** `inc/ai-ai-dedupe.php` — two `add_filter('wpai_feature_{meta-description,excerpt-generation}_enabled','__return_false')` calls disable `ai/ai`'s two features that duplicate SN's own generators. **Also fixes a latent bug:** with no third-party SEO plugin active, `ai/ai`'s meta-desc feature emitted its *own* `<meta name="description">` on `wp_head` pri 1, competing with SN's SEO module → potential double tag. Hiding the feature stops its emit. SN's generators + `ai/ai`'s 4 non-duplicated features (editorial notes, summary, suggest cats/tags, title) untouched.
- **B. AI prepopulation at publish (deferred).** `inc/ai-prepopulate.php` (engine) + `inc/ai-prepopulate-notice.php` (notice/dismiss). On the first `draft→publish/future` transition (scoped to `SN_POST_SETTINGS_POST_TYPES`), schedules a `wp_schedule_single_event` cron job that auto-fills **empty-only** `_sn_meta_description`, `post_excerpt`, `_sn_og_card_title` by calling the SN `*_impl()` functions **directly** (NOT the abilities — cron has no user, so the ability `edit_post` permission check would block it). Each filled field sets a `_sn_autogen_*` sentinel.
- **C. `concise` param** added to all 3 ai-post-editor ability schemas; meta-desc + excerpt impls honor it (tighter system instruction + lower max_tokens). Meta-desc concise has a `snt_ai_truncate_meta_description()` word-boundary guard (≤155 chars — models overshoot). OG-title accepts-and-ignores. **Manual generation unchanged** (default false).
- **D. Consolidated notice.** One info line at the top of the SN meta box listing the auto-generated fields, with `[Dismiss]` (REST `POST /signal-noise/v1/prepop/dismiss`, perm `edit_post`). Clears on the next editor save OR dismiss — shows exactly once.

**Gates at ship:** plugin **37 suites / 1192 assertions / 0 failures**; phpcs **85 files / 0 errors** (falsification-confirmed on the new file). Theme unchanged at **v9.9.0**.

## How it was built (the rigor — reusable pattern)
1. `superpowers:brainstorming` — settled 5 product/UX decisions with the user (scope=both; defer via `wp_schedule_single_event`; per-field length budgets; consolidated show-once notice; cleanup=hide both duplicates).
2. **Grounding audit** (3 parallel agents) of the upstream `ai/ai` plugin (`github.com/WordPress/ai`, v1.0.1) + SN's AI surfaces. This **overturned the stub's assumptions** — see spec §0: `ai/ai`'s panels are JS editor plugins (`remove_meta_box` is a no-op → use the `wpai_feature_*_enabled` filters); excerpt is *also* duplicated; abilities return `description`/`excerpt`/`title` (not `text`); excerpt is the core `post_excerpt` field; OG-title impl self-persists + rebuilds the PNG.
3. Spec → plan (5 parallel source-reads for exact code) → one implementer (7 TDD tasks) → **adversarial review panel** (5 lenses × refute-by-default verify): 8 raw → 6 confirmed (1 MED + 5 LOW), 2 correctly dismissed → fixed → final holistic review → **SHIP-READY**.

**Lesson reinforced:** the review's MED finding was prepop coupling its post-type gate to the unrelated `sn_webhook_post_types` filter (over-applying "mirror the webhook guard") — a webhook CPT would've silently triggered AI spend with no surface for the result. Fixed to use `SN_POST_SETTINGS_POST_TYPES`. See `[[feedback_verify_impl_contracts_behavioral_tests]]`.
