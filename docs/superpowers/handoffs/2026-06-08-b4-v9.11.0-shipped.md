## ⚠ The HIGH the green suite missed (the lesson of this cycle)
The build passed 26/676 green + a "0 confirmed findings" review — yet the **sidenote/pull-quote blocks rendered EMPTY on the front end.** Both declared `source:html` attributes, but **a dynamic block's render callback receives ONLY comment-delimiter attrs server-side — WordPress never sources `source:html` in PHP** (verified vs `wp-includes/class-wp-block.php`). So `render.php` read `$attributes['content'] = ""`. The green fixture hid it by injecting `$attributes` directly into `render.php` (false-green). **Fix:** plain attributes (value persists in the block's comment JSON → populated server-side) + `save()` returns `null` (fully dynamic, no validation churn). See `[[reference_dynamic_block_source_html_empty_server_side]]`.

Two process notes that made this nearly slip:
1. **The "go faster" integrated review→fix→gate workflow reported `0 confirmed` falsely** — its 3-lens refute-by-default verify stage CRASHED (~17 `StructuredOutput` failures). A crashed lens returns `null`; the confidence logic (`>=2 of 3 lenses refuted===false`) treated crashes as refutations, so real HIGH/MED findings were dropped as "refuted." **Distinguish errored from refuted in any voting workflow.** See `[[feedback_workflow_verify_crash_not_refute]]`.
2. **Plan mode + read-only Explore agents** then re-adjudicated the un-verified findings against real WP-core source and confirmed BLK-1/2 (HIGH) + BLK-3/BND-1/BND-4 (MED) were all real. Don't trust a green/clean result when the verification machinery itself failed — re-verify.
